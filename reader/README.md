# 반야심경 읽기·대조 시범판

번역 자료를 한 번 기록하고 같은 자료에서 읽기 문서와 웹 화면을 만든다. 문서의 표시 순서와 번역 자료의 구조를 분리하여, 번역을 고치는 일과 화면을 고치는 일을 각각 검토할 수 있다.

## 수정할 곳

- [구절별 자료](../data/heart-sutra.json): 한글 번역, 한문, 현토, 번역 주, 용어 대응과 연결의 편집 원본이다.
- [원전 고정 기록](../data/source-lock.json): CBETA 커밋·URL·전체 파일의 SHA-256을 고정한다. 원문 교체는 별도 대조와 검토가 필요하다.
- [HTML 틀](index.html), [화면 스타일](assets/reader.css), [화면 동작](assets/reader.js): 본문을 다시 쓰지 않고 표시를 바꾼다.
- [번역 근거](../SOURCES.md): 서지·해석·검토 이력의 연구 문서다. 그 안의 기존 용어 표는 반입 당시 기록으로 보존한다. 현재 용어 대응은 JSON에서 수정하며 새 판단의 근거와 날짜는 연구 문서에도 남긴다.

[기존 독송 문서](../translation/01-heart-sutra.md), [구절별 대조 문서](parallel.md), [용어 대응표](terms.md), `dist/` 웹 화면은 Python으로 생성한다. 생성된 문서에서 직접 번역을 고치지 않는다. 원본 JSON을 수정하고 생성 명령을 실행한다.

## 자료 구조

`schema_version: 1`은 반야심경 시범 구조다. 다른 경전에 일괄 적용한 공통 규격은 아니다.

| 항목 | 역할 |
| --- | --- |
| `work_id` | 경전 식별자 |
| `units` | 고정 구절 ID `hs-001`~`hs-016`, 편집상 소제목, 한문, 현토, 관련 주석 ID |
| `translation_blocks` | 기존 11개 한글 문단. `segments`가 구절 ID와 번역 조각을 보존한다. |
| `notes` | 주석 ID, 표시 번호, 기존 번역 주의 문구 |
| `terms` | 용어 ID, 한역 용어, 관용 독음, 산스크리트 대조 어구, 채택 번역, 판단, 관련 구절 ID |
| `import` | 최초 반입 커밋과 기존 문서의 줄바꿈 정규화 후 체크섬 |

구절을 추가·분할할 때 기존 ID를 자동으로 다시 매기지 않는다. 번역 조각의 공백·문단 경계도 자료다. 예를 들어 `hs-014`는 한문의 한 구절이지만 한글에서는 두 문단에 걸친다. 화면을 맞추려고 문단을 재작성하지 않았다. 소제목·번호·연결은 편집자의 안내이며 경문 자체가 아니다.

산스크리트 칸은 기존 근거 기록에서 추출한 비교 어구다. GRETIL의 실제 표기와 다른 교정본의 표기를 구별한 설명을 보존한다. 한문 구절마다 산스크리트 전문이 일대일로 정렬되었다고 주장하지 않는다. 산스크리트 전문이나 빨리어 원전을 새로 수록하지 않았다.

`conventional_reading`은 한역 용어의 관용 독음이다. 일반적인 한국어 번역어를 출처별로 조사한 결과와는 구별한다. 다음 단계에는 `출처·판본·번역어·구절`을 갖춘 별도 용례 목록을 연결할 수 있다. 조사하지 않은 대응을 일반 번역의 표준이라고 표시하지 않는다.

## 생성과 검증

저장소 최상위에서 실행한다. Python 표준 라이브러리만 쓰며 추가 패키지는 필요 없다.

```powershell
uv run python scripts/build_reader.py
uv run python scripts/build_reader.py --check
uv run python scripts/test_reader.py
uv run python scripts/verify_translation.py
```

처음에는 고정 CBETA XML을 내려받기 위해 네트워크가 필요하다. 이후에는 `.cache/T08n0251.xml`의 전체 파일 체크섬을 매번 확인한다. `--fetch-source`로 다시 내려받아 확인할 수 있다. 배포본의 `sources/T08n0251.xml`은 원래 헤더를 포함한 전체 파일이다. 제목·역자·서문을 제외한 경문 260자만 화면 한문과 대조한다. 표점은 기존 표시를 보존하며 한자열의 일치를 검사한다.

```powershell
uv run python scripts/build_reader.py --check-migration
```

이 명령은 **최초 이관 검사**다. 반입 커밋의 Markdown을 정확히 복원하는지 확인한다. 이후 번역을 의도적으로 수정한 뒤에는 같을 수 없으므로 통상 검사와 구별한다. 최초 시범판은 이 검사를 통과했다. `scripts/import_reader.py`는 최초 반입의 재현 기록이며 편집 원본이 있으면 덮어쓰기를 거부한다.

```powershell
uv run python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

그 뒤 `http://127.0.0.1:8765/`를 연다. 외부 글꼴·스크립트·분석 서비스에 의존하지 않는다. 글자 크기와 현토 표시만 현재 브라우저에 저장한다. 검색도 브라우저 안에서 처리한다. JavaScript를 끄면 모든 절을 순서대로 읽고 고유 링크를 따라갈 수 있다.

다른 배포 폴더로 출력할 때에는 `--site-dir C:/절대/경로/dist`를 쓴다. 사이트 계정과 연결 정보는 이 공개 번역 저장소에 넣지 않는다.

## 이번 시범판의 범위

한글 이어 읽기, 한문·현토 대조, 구절별 주석 열기, 용어 대응, 본문·원어 검색, 글자 크기 조절과 고유 링크를 제공한다. 검증은 누락·문자 변조·잘못된 연결·중복 ID·생성 결과의 재현성을 확인한다. 번역 의미나 학술적 감수를 자동으로 확정하지 않는다.

확대 전에는 실제 독자의 문단 길이·글자 크기·주석 이동 경험을 검토하고, 다른 경전의 문단·게송·장 구분·복수 원전도 손실 없이 표현되는지 추가 시범으로 확인한다.
